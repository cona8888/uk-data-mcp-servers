# Project instructions

Repository: `cona8888/uk-data-mcp-servers`

## Scope

Develop read-only MCP tools for UK public infrastructure, geological and environmental data. Keep provider licences, attribution, coverage, dates, units and quality flags with every result. This is a preliminary research and screening tool, not a certified engineering design or safe-to-dig service.

## Repository safety

- Inspect the current branch, remote, relevant files and existing changes before editing.
- Preserve unrelated work and published history. Do not force-push or delete branches or repositories without explicit authorisation.
- This repository was created as public by its owner. Never commit credentials, private project documents, personal information, restricted provider data, local environment files or caches. Do not change repository visibility without authorisation.
- Keep original software notices and distinguish code licensing from provider-data licensing.
- Do not copy code from external projects without checking and preserving its licence.

## Completing requested work

The owner has requested that completed project work be saved to GitHub during active tasks. When the requested work and destination are clear, review the diff, run appropriate checks, commit and upload the task changes, then verify the remote commit. Routine saves do not require another conversational confirmation. Respect tool approvals and branch protection.

- Use the existing branch unless the task or protection rules require a task branch.
- Use expected-head checks when available. If a branch advances, inspect and reconcile before retrying; never blindly overwrite.
- Do not merge pull requests without authorisation.
- Report the branch, commit and checks actually performed. Label inherited validation separately from checks rerun during the current task.
- Preserve failed or incomplete work and report blockers honestly.
- These instructions apply during active tasks; they do not create background automation or grant additional permissions.

## Engineering evidence

Do not invent missing soil parameters or treat an empty query as proof of safety. Separate observations, correlations, estimates and design assumptions. Keep unknown parameters explicitly unknown unless an independently reviewed estimation method is requested.
