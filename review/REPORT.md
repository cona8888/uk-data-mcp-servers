# Stakeholder validation of the UK Civil Data MCP

**2 November 2026 | Application: `c7debb9cb833f9b8fa81ef25f16f84ad1be8599f`.** Pilot for human-reviewed public-data desk studies. Do not use for network capacity, utility location/clearance, structural or geotechnical design values, or planning permission. This review branch adds research scripts, workflows and findings only. No application or original test code was changed.

## Evidence and method

The [timed run](https://github.com/cona8888/uk-data-mcp-servers/actions/runs/41449072359) and [independent-distance diagnostic rerun](https://github.com/cona8888/uk-data-mcp-servers/actions/runs/41449419345) checked that src/, tests/ and pyproject.toml matched the target revision. Both ran the installed civil gateway through a real stdio MCP subprocess, exercised synthetic faults, and compared individual map event IDs with a separate calculation from the DfT annual collision file. [All five ordinary CI configurations](https://github.com/cona8888/uk-data-mcp-servers/actions/runs/41449418501) passed with the diagnostic harness present. Successful execution of the benchmark is not a pass for every behaviour: it records counterexamples as well as successes.

[Six independent model contexts](https://github.com/cona8888/uk-data-mcp-servers/actions/runs/41448785644) used Qwen2.5-Coder-1.5B-Instruct, revision 2e1fd397ee46e1388853d2af2c993145b0f1098a, on one runner, with public code excerpts and a bounded directory tool. Each selected the source tool. Perspectives: general, GI, water, gas, electricity, and council/developer. These are not human reviewers or institutional endorsements. Agent statements were checked against code or execution: gas and electricity handoff concerns were supported; the water claim that a company argument is required was false. The broad claim that exceptions never produce actionable errors was also contradicted by the missing-cache test.

## Observed benchmark

- Real stdio: 28 tools, all annotated read-only. Three cold process starts to `list_tools`: 942.38, 940.27, 933.32 ms. Thirty warm `civil_coverage('water')` calls in one process: median 1.729 ms; nearest-rank p95 1.823 ms.
- Synthetic bounded BGS point scans, 7 runs per size, no real network or throttling: 10/100/1,000 candidates took 74.833/87.857/221.589 ms median; 1/1/10 upstream mock requests; all matches counted, only five shown.
- Digbeth, 250 m each side: 1.627 s, 9 requests, 200 candidates, 83 returned across five layers: 40 borehole index records (all had a precision field), 5 Canal & River Trust bridges, 14 EA defences, 22 mapped 2025 injury collisions, 2 wards. Defence contacts occurred about 314 m and 359 m from the route origin. Bordesley & Highgate was traversed; Nechells was near only. The compact structured result was 62,168 bytes, versus 134,121 bytes for the serialised MCP result including text and structured forms. These are not LLM token counts. Repeat live duration was 1.321 s.
- Leeds, 250 m, collision layer only: 2.176 s, 3 requests, 53 candidates, 31 returned; repeat 2.248 s. One sample per workload per run, four reported CPUs, Ubuntu/Python 3.12.15; neither throughput nor a service-level commitment. No multi-user saturation, outage-frequency, visual-browser or human field trial was performed.
- Reference: [DfT 2025 STATS19](https://www.gov.uk/government/statistical-data-sets/road-safety-open-data), 101,525 rows, 2 without usable grid coordinates, SHA-256 e699c19bdb82e47e449b6f3381ac87631865f6a31cef118c9955ba80ca870e2b. Independent point-to-segment calculation used national CSV eastings/northings against the server's projected route vertices. Compared with that definition: Digbeth TP 22 / FP 0 / FN 0; Leeds TP 31 / FP 0 / FN 1. Max matched offset differences 0.790 and 1.786 m. Neither result was display-truncated. The Leeds missing ID was present in the pre-filter candidate set: 249.701 m using national CSV coordinates versus 250.735 m using the projected map coordinates. Thus the 250 m test flipped; no page was lost. Both products derive from DfT; these are implementation checks, not positional ground truth or national recall estimates.
- The leakage call gave Severn Trent 17.2% of distribution input in 2024/25; the planning point returned Birmingham LPA. Live HPI returned HTTP 403 for Birmingham January 2024 on run 1 and £223,452 on run 2. Do not treat a transient failure as a zero or mix live and prepared vintages silently.

## Decisions by user

| User | Suitable use now | Missing evidence or next action |
|---|---|---|
| First-time user | Run a named task; recovery for an unprepared census table includes the exact prepare command. | Only 6 of 12 selected phrases reached the intended category. Provide plain-language tasks, including no-data and restricted-access guidance. |
| Geotechnical engineer | Identify nearby GI records and decide which originals to read. | Check the original log, strata, elevations/datum, date, position precision and applicability. A point or formation label cannot specify design parameters. |
| Water company | Identify mapped flood-defence contacts and dated company-level performance. | No local pipe invert, pressure, sewer capacity or diversion conclusion. Separate maps and developer enquiries are operator workflows. |
| Gas operator | Restricted-access signposting under 'buried pipelines'; an unsupported gas layer errors rather than fabricating lines. | 'Gas main' and 'underground utilities' did not reach that route. Provide authorised operator/NUAR handoff, never a public-map clearance. |
| Electricity network operator | General energy context. | 'Electricity cable', 'grid capacity' and 'electricity grid' failed. No local feeder capacity or 2 MW connection decision. Distinguish indicative import/export headroom from a formal application. |
| City council | Screen wards, injury events, nearby assets and mapped intersections for options appraisal. | Ward proximity is not beneficiary count; collision counts are not rates. Retain coordinate basis and flag boundary-sensitive events. |
| Developer | Identify an English planning authority at a point and obtain dated area housing context. | Polygon input rejected by the corridor tool; no parcel-wide permission, valuation or servicing conclusion. Obtain full site plans, authority records and network responses. |

## Priority code findings and acceptance tests

1. **Wrong jurisdiction can resemble a complete zero.** `corridor.py::_layer` gates on caller-supplied nation. Edinburgh geometry labelled England plus a mock empty EA response returned `empty`, 0 matches, `candidate_scan_complete=true`. Validate nation against versioned polygons; split or reject cross-border routes. A deliberately wrong nation must not produce an in-coverage zero.
2. **Saved evidence can export a contradiction.** `corridor_schedule.py::write_schedule` accepted a synthetic `nearby_only` feature with offset 123 m, zero contacts and a contact at −5 m. Require the route-length bounds, relation, count and event list to agree; reject the invalid report without replacing an existing CSV.
3. **A raw-source hash does not validate the derived cache.** `civil_tables.py::area_record` accepted a changed district count of −7 with the original source SHA intact. This involved editing a local fixture, not manipulating DfT. Validate non-negative integer counts and severity sums. Provide a derived-index digest and a way to compare with a trusted manifest or rebuild from the source. A digest stored alongside an untrusted file is not authentication.
4. **Contradictory paging and an unrecognised CRS can pass.** `corridor.py::pages` accepted `numberMatched=0` plus one feature as `ok`/complete. `features()` accepted `FAKE:143260` because it contains the string `4326`. This fixture used native borehole grid coordinates; it proves weak metadata validation, not an observed real displacement. Parse exact supported CRS identifiers and reconcile totals/IDs before marking complete.
5. **Vocabulary and handoff.** `civil_coverage` missed 'gas main', 'electricity cable', 'underground utilities', 'grid capacity', 'electricity grid', 'sewer capacity'. 'Buried pipelines', 'energy', 'water', 'boreholes', 'house prices', 'planning' matched. Add tested synonyms and an operator/nation-aware next step for restricted, unsupported and unindexed products. Retain no-invention behaviour. Use unseen professional phrasing in later human trials.

Positive controls: duplicate source IDs produced `partial`, upstream non-finite JSON produced a source error with unknown match count, unsupported NI collision geography was rejected, and an absent census snapshot returned a specific preparation command. Preserve these distinctions. For threshold-sensitive evidence use published native coordinates where justified, retain the original point/CRS, flag ambiguous membership and differentiate 'all returned candidates examined' from 'complete inventory'.

## Reproduction and scope

Fetch and switch to `review/civil-readiness-2026-11-02`, install from the checkout in a fresh virtual environment with `python -m pip install .`, then `python review/benchmark.py`. This makes bounded live requests and downloads one official annual CSV for the independent comparison. The programme writes benchmark.json. Model suggestions are retained separately from measurements. All data are public or synthetic. No human time-to-task or operator internal systems were tested. Before wider rollout: first fix geography and data integrity, then utility handoffs, then run observed user tasks and concurrent/load tests on rural, cross-border and dense urban routes.
